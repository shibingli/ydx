# ydx/pool 超低延迟协程池 Implementation Plan

> 实现期基准调优记录：`sync.Cond` 唤醒改为无锁唤醒通道 + 完全空闲时的直接握手通道；
> 默认 `SpinCount` 从 64 调整为 32；完成计数改为 worker 独占原子计数、等待计数按 64 批量
> 递减。最终架构与默认值以 `docs/superpowers/specs/2026-11-03-pool-design.md` 为准。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 ydx 新增 `github.com/shibingli/ydx/pool` 模块，以分片无锁环实现纳秒级任务、超低延迟、高并发的同步/异步协程池。

**Architecture:** 分片 MPMC 环 + 全局 fallback；提交方轮询分片，worker 优先消费 home 分片、空闲时工作窃取、最后自旋/休眠。任务内联在环槽中，fire-and-forget 零分配；统计按 worker 批量 flush；panic/context/关闭/扩缩容全部覆盖。

**Tech Stack:** Go 1.27.3、`sync/atomic`、`sync.Cond`、`runtime/debug`、`context`；仅依赖仓库内 `errs`。

**Spec:** `docs/superpowers/specs/2026-11-03-pool-design.md`

## Review Focus

- Close/Shutdown 与新提交并发：被接受但未执行的任务必须以 `ErrPoolClosed` 完成 future，不能挂起。
- 唤醒丢失：生产者入队与 worker 休眠之间的交错不能让任务长期滞留。
- 环回绕与并发生产者/消费者：长期运行后不能重复/丢失任务。
- panic/ErrorHandler/PanicHandler 自身 panic：不能杀死 worker。
- 缩容/窃取：worker 数变化后所有分片的任务仍必须被处理。
- 批量取消：`CallBatch` 的 context 取消不能返回未初始化结果或死锁。

- [ ] **Step 3: 实现**

- `completion` 包含 `done atomic.Bool`、`ch chan struct{}`、`value R`、`err error`。

- [ ] **Step 3: 实现引擎**

- `newEngine`：分片数取 2 的幂；每分片 `newRing[J](perShard)`；fallback 环；
  启动 workers；启动 `wg.Wait` 关闭 `done` 的协程。
- 提交：轮询选择分片 → 本地环 → fallback → 阻塞/`ErrQueueFull`；成功后
  `pending.Add(1)`、唤醒 sleeper、按需 Signal space 等待者。
- worker：home → fallback → 全分片窃取 → 自旋 → 登记 sleeper → 再检查 → `cond.Wait`；
  关闭时按 graceful 执行或丢弃。
- 阻塞提交用 `spaceMu/spaceCond/spaceWaiters`；worker 出队后仅在有等待者时 Signal。
- 唤醒用 `mu/cond/sleepers`；提交后仅 `sleepers>0` 时加锁 Signal。
- 统计：worker 本地 `processed/failed/panicked` 每 64 个 flush 到原子计数器；
  `Submitted` 由 ring tail + fallback tail 派生；`Queued` 为近似值。
- `close`：CAS closed；设置 graceful；Broadcast 两个 cond；等待 `done`；最终 drain/discard。
- `shutdown(ctx)`：首个关闭者决定 graceful；等待 `done` 或 ctx。
- `resize`：mu 下增减 workers；扩容启动新 worker；缩容 Broadcast，worker 在 park 前退出。
